# Architecture

```
whynet/
  main.go                  Wails window options (900x660, min 520x520, Windows theme = system)
  app.go                   what the window calls: Info, Check (emits a "step" event per finished step),
                           CheckInBrowser + FinishBrowser (visible window, "browser-progress" events),
                           Report / SaveReport (native Save dialog) / CopyReport (clipboard); verdict tones;
                           hostViews joins the content check and the browser per server for "Details"
  frontend/                vanilla JS + Vite; index.html (input bar), src/main.js (state -> render, fitWindow
                           sizes the window to the content after every render),
                           src/style.css (mockup variant A tokens, dark only; main.go sets a dark title bar);
                           fonts Golos Text + JetBrains Mono from @fontsource, bundled into the exe;
                           wailsjs/ holds bindings generated by `wails build` (committed)
  app_har.go               the person's own browser record: ReadHAR (pasted), PasteHAR (clipboard), ReadHARFile
                           (dropped, main.go turns file drop on), PickHAR (Open dialog) -> HARInfo; CompareHAR
                           adds the "own" step to the last check (checking the record's site first when it differs)
                           and matches the rules again; OwnView for the "Details" table
  app_live.go              the stability check for the window: StartLive (emits "live-tick" about once a
                           second, "live-done" after an hour), FinishLive, CancelLive, MarkLag; Ctrl+Alt+L hotkey;
                           compare with the previous check; LiveView for the window
  cmd/whynet-cli/          console front end: progress, verdict, -json, -save (AI report); live.go: -live [-for]
  internal/probe/          the checks; Env holds everything external, tests swap it
    har.go                 ParseHAR: a HAR record down to address (no query), kind, status, error, phases, IP
                           (cookies, headers, bodies are never decoded); OwnStep compares it with whynet's browser
                           (the same file, else the same server) into `own.*` facts; DefaultBrowserFamily
                           (browser_windows.go) picks the instructions
    probe.go               Run, Step/Result, Env, Target (input -> ASCII host + path), local/dns/tcp steps
    tls.go, http.go        tls step (real SNI, control SNI, alt address), http step
    classify.go            error -> fact words (Windows WSA codes), fake-ip range
    doh.go                 DNS-over-HTTPS JSON client (1.1.1.1, then 8.8.8.8)
    local.go               hosts parsing, Cloudflare trace, ASN (Team Cymru over DoH), IP masking, the clock
                           fallback that checks the certificate at its own time (verifyAnyTime)
    local_windows.go       route, OS, Adapters (GetAdaptersAddresses: kind wifi/cable, index, GUID), proxy, hosts, clock
    server.go              ResolveServer: a stability check's server from an IP, a name or a URL (DoH behind fake-ip)
    browser.go             "browser" step: BrowserSession drives Edge/Chrome over the DevTools protocol
                           (x/net/websocket), fresh temp profile, no sign-in/sync; hidden and automatic, or
                           visible (BrowserOpts: Done, Progress) for the person; Network events -> per-server
                           totals, errors, speed; DOMContentLoaded/load timing; page title+text for markers;
                           per request DevTools' ResourceTiming split into phases (queue, dns, connect, tls,
                           wait, download) -> SlowFile list: failed, never answered, or 3 s+ (images, scripts,
                           styles, fonts; media only on failure), with the phase that took the time
    netlog.go              visible window: a plain browser (no debugging port: anti-bot checks spot it) with
                           --log-net-log; the log is tailed live and parsed into the same per-server totals;
                           the page's own requests are those whose network_isolation_key top site is the page's
    browser_windows.go     find Edge, else Chrome (App Paths, Program Files, LocalAppData); hide its window;
                           window title and WM_CLOSE for the plain window (one shared EnumWindows callback)
    resources.go           "res" step: content servers from the HTML (x/net/html), from markers' `related`
                           and from the browser's failures and late files, then the rest it used (ads last); DNS/TCP/TLS/control + one sample file per server,
                           6 at a time, up to 20; stall watchdog and speed; ping = 5 TCP connects (TLS
                           handshakes behind a fake-ip router), median + tries that lost a packet
    dpi.go                 bundle folder from a path, zapret hostlist matching (plain = with subdomains, ^ = exact)
    dpi_windows.go         DPI-bypass tools: processes (+exe, command line), services, WinDivert driver; no admin needed
  internal/live/            the stability check (design: stability.md); Env holds everything external
    live.go                Link, Result and the types the window and the report read; the two control addresses
    session.go             Start: router (physical adapter's gateway), the node beyond it (first trace round),
                           the server; a tick every 500 ms pings every link at once; a trace round every 5 s;
                           Wi-Fi every 5 s; a stand-in for a server that ignores pings; Finish/Cancel/auto-stop
    analyze.go             recording -> facts: spikes, confirmation by the links behind, "по его вине", states,
                           episodes, the 60 s rhythm, lag marks, buckets, the thinned chart
    trace.go               parallel TTL rounds, per-hop totals, reading the route (real loss, where it jumps)
    icmp_windows.go        ICMP echo with a TTL (iphlpapi IcmpSendEcho), no admin
    wlan_windows.go        Wi-Fi of the router's adapter (wlanapi): signal, RSSI, channel, PHY, rate, SSID
    hotkey_windows.go      Ctrl+Alt+L (RegisterHotKey on a locked thread with its own message loop)
    env_windows.go         DefaultEnv: the real network
  internal/report/         the AI report (Markdown) and its file name; Version (a var, settable with -ldflags);
                           live.go: the stability report, link names and hop notes shared with the window
  internal/update/         newest GitHub release (asset whynet.exe + its SHA-256 digest), version compare,
                           download and swap: running exe -> exe.old, new -> exe; CleanOld on next start
  rules/                   rules engine + data, embedded: diagnoses.yaml, live.yaml (stability verdicts,
                           LoadLive), markers.yaml, ads.txt.gz (76k ad
                           and tracker domains, StevenBlack/hosts MIT, ads-LICENSE.txt)
  tools/adlist/            rebuilds rules/ads.txt.gz from the upstream list
  locales/                 every user-facing string: ru.yaml (diagnoses, live_diagnoses, live, steps, report,
                           ui, values, notes)
```

## Data flow

```
input -> probe.Target -> probe.Run(ctx, Env, onStep) -> Result{Steps[{facts, evidence}], Mask}
      -> rules.Match(rules, Result.Facts()) -> Verdict{id, confidence}
      -> CLI / UI text from locales by id ({fact} placeholders filled)
      -> report.Markdown(Result, Verdict, texts, hide) -> .md file

stability: target -> live.Start(ctx, Env, target, onUpdate) -> Session (ticks, trace rounds, lag marks)
      -> Session.Finish -> live.Result{Facts, Links, Trace, WiFi, Lags, Spikes, Buckets, Chart, Mask}
      -> rules.Match(rules.LoadLive(), Result.Facts) -> Verdict (live_* texts)
      -> report.LiveMarkdown(Result, Verdict, texts, hide, previous) -> .md file
```

- The window renders only what Go sends: step names, verdict texts with placeholders filled, one-line notes under failed steps (`notes` in ru.yaml, matched by `key=value`), UI strings. The UI never builds its own diagnosis text.
- Probes only gather facts and evidence; all judgement is in `rules/diagnoses.yaml`. Markers (`markers.yaml`) are lowercase substrings probes use to label what they saw (stub pages, geo-block texts, HTTPS interceptors, VPN adapters).
- Every step runs under panic recovery and its own timeouts; a failed step is recorded and the next steps still run (skipping what they cannot do).
- DPI-bypass tools (zapret/Flowseal, GoodbyeDPI) rewrite packets through WinDivert for every process, whynet included, so the checks see what the browser sees. The bundle folder is found from the process exe, the service command line or the driver path, in that order; its lists tell whether the site is covered. Tool names, services and drivers are data in `markers.yaml`.
- The report masks private values (public IP to its first two octets, computer and user names as a safety net) by plain replacement over the finished text, raw JSON included.

Stability check facts (`internal/live/analyze.go`; ids: router, beyond, ctl_ru, ctl_world, server):

| Fact | Values |
|---|---|
| `live.router`, `live.beyond`, `live.server` | stable, unstable, silent (never answered), none (no such link) |
| `live.internet` | unstable (both controls), silent (both), stable |
| `live.<id>_addr`, `_median_ms`, `_p95_ms`, `_loss_pct`, `_own_pct` | the link's address and numbers over the session (own: "по его вине") |
| `live.router_kind` | wifi, cable, other |
| `live.path_vpn` | true: the default route goes through a VPN adapter on this PC |
| `live.server_stand_in` | the hop pinged instead of a server that ignores pings |
| `live.router_periodic_s` | 60: the router's own spikes repeat about every minute (background Wi-Fi scan) |
| `live.wifi_signal`, `live.wifi_band`, `live.wifi_rssi` | average signal %, 2.4 / 5, last RSSI dBm |
| `live.lag_marks` | how many "лагнуло" marks (bookmarks: each looks back 10 s for the nearest jump; no rule uses them) |
| `live.route_jump_hop` | TTL where the delay goes up and stays |
| `live.seconds`, `live.too_short` | length; true under 30 s |

A link's trouble (a spike: an answer over max(3 × median, median + 50 ms), or a loss) counts only when some link behind it shows trouble at the same tick, and is the link's own only when every nearer link was calm. A link is unstable when its own trouble is ≥ 2 % of the ticks, or (not for `beyond`, an intermediate router answering pings to itself) when p95 − median of its own view reaches 50 ms (router 20 ms).

Step order: local, dns, tcp, tls, http, browser, res. The browser runs first so the content step can explain the servers it failed on. Both content steps run only when the page itself loaded over HTTPS.
